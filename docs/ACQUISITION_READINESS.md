# JANUS HELIOS — Acquisition Readiness Index

This page is the transaction-facing map for a potential HELIOS buyer, seller counsel and technical due-diligence team.

It is designed to remove ambiguity **before** a serious offer, while preserving the factual boundary that HELIOS is currently a public capability/evaluation prototype rather than a certified production gambling or compute platform.

## 1. What is being sold?

Default answer: **only the expressly listed HELIOS assets**.

- Purchased assets: [`../legal/PURCHASED_ASSETS_SCHEDULE.md`](../legal/PURCHASED_ASSETS_SCHEDULE.md)
- Excluded assets: [`../legal/EXCLUDED_ASSETS_SCHEDULE.md`](../legal/EXCLUDED_ASSETS_SCHEDULE.md)
- Buyer configuration/handoff: [`../BUYER_HANDOFF_SPEC.json`](../BUYER_HANDOFF_SPEC.json)

`DIVINE_REALM`, `SSlot`, other JANUS repositories, future inventions, general know-how and seller personal accounts are not included by implication.

## 2. Who/what created the technology?

- Background IP and provenance: [`../legal/BACKGROUND_IP_AND_PROVENANCE.md`](../legal/BACKGROUND_IP_AND_PROVENANCE.md)
- Third-party notices: [`../THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md)
- Machine-readable diligence record: [`../.janus/HELIOS_DUE_DILIGENCE.json`](../.janus/HELIOS_DUE_DILIGENCE.json)

The repository discloses AI-assisted development rather than pretending that every line was manually typed. A complete contribution-history review and seller attestation remain closing steps.

The HELIOS swarm-dispatcher acknowledges lineage from `Hawkar-usls/janus-distributed-ai-swarm`, which is published under MIT by the same GitHub owner. Any applicable MIT notices must remain with covered material.

## 3. How is the exact product frozen?

- Release/hash procedure: [`RELEASE_AND_HASHING.md`](RELEASE_AND_HASHING.md)

A transaction should identify exact commit SHA, tree SHA and a SHA-256 file manifest. A signed release/tag is preferred when available.

The repository does **not** claim that an unsigned commit is signed.

## 4. What must pass before technical acceptance?

- Acceptance criteria: [`../legal/ACCEPTANCE_AND_HANDOVER.md`](../legal/ACCEPTANCE_AND_HANDOVER.md)

Acceptance is based on objective delivery checks, not whether the buyer later earns a particular amount of money.

The complete test suite must actually be executed on the exact closing snapshot before anyone claims the closing snapshot is `PASS`.

## 5. What does support include?

- Transition support: [`../legal/TRANSITION_SUPPORT_SCOPE.md`](../legal/TRANSITION_SUPPORT_SCOPE.md)

Transition support is bounded knowledge transfer. New development, provider integration, production operations and regulatory work require separate scope unless explicitly purchased.

## 6. What does acquisition *not* prove?

Buying HELIOS does not itself prove or deliver:

- production profitability;
- real data-center offload percentage;
- token-price appreciation;
- real-money gambling certification;
- RNG/RTP laboratory certification;
- production compute-provider settlement;
- privacy/security certification;
- regulatory approval;
- guaranteed provider or sponsor participation.

The sponsor/provider validation gate and illustrative economics remain documented in [`COMMERCIAL_THESIS.md`](COMMERCIAL_THESIS.md).

## 7. Deal mechanics

- Transaction guardrails: [`../legal/TRANSACTION_GUARDRAILS.md`](../legal/TRANSACTION_GUARDRAILS.md)

Preferred control-transfer order:

```text
SIGNED AGREEMENT
→ CONFIRMED FUNDS / ESCROW
→ EXACT RELEASE SNAPSHOT
→ BUYER-CONTROLLED REPOSITORY/ACCOUNTS
→ OBJECTIVE ACCEPTANCE
→ FINAL PAYMENT RELEASE
```

Seller personal GitHub/email passwords, MFA secrets and recovery credentials are never handover assets.

## 8. Closing items that cannot be solved by repository text

Before a six-figure acquisition closes, the parties still need real-world execution of:

1. qualified transaction counsel review;
2. seller identity/authority documentation;
3. full contribution-history review;
4. automated SBOM/licence scan;
5. full tests on the exact closing commit;
6. signed release/cryptographic attestation when feasible;
7. trademark clearance if a brand is transferred;
8. patent review if patent rights are negotiated;
9. escrow/payment arrangements;
10. signed Asset Purchase Agreement / IP Assignment;
11. signed acceptance certificate.

These are deliberately shown as closing gates instead of being falsely marked complete.

## Canonical diligence rule

> **Exact assets. Exact snapshot. Disclosed provenance. Objective acceptance. Factual warranties only. No hidden scope and no invented production claims.**
