# JANUS HELIOS — Acquisition Closing Checklist

> Operational checklist for a potential transaction. It is not a substitute for a signed agreement or qualified legal/tax advice.

## Phase 0 — Internal seller readiness

- [ ] Freeze the proposed sale perimeter: HELIOS-only or expanded package.
- [ ] Review `PURCHASED_ASSETS_SCHEDULE.md`.
- [ ] Review `EXCLUDED_ASSETS_SCHEDULE.md`.
- [ ] Confirm whether HELIOS/JANUS names or marks are included.
- [ ] Confirm whether `DIVINE_REALM` / `SSlot` are excluded or separately priced.
- [ ] Complete contribution/provenance review.
- [ ] Complete SBOM/licence scan.
- [ ] Resolve any incompatible licence finding.
- [ ] Run full tests on a candidate release snapshot.
- [ ] Prepare signed seller ownership/authority disclosure with counsel.

## Phase 1 — NDA / technical introduction

- [ ] NDA identifies already-public information as excluded from confidentiality.
- [ ] NDA covers non-public roadmap, pricing, provider discussions and private architecture disclosed later.
- [ ] Buyer receives read/evaluation access only.
- [ ] No seller personal credentials or admin control transferred.
- [ ] No representation that an evaluation demo is production-certified.

## Phase 2 — LOI / Term Sheet

- [ ] Transaction type defined: licence / exclusive licence / asset sale / full IP acquisition.
- [ ] Headline price and currency defined.
- [ ] Deposit/escrow structure defined.
- [ ] Exclusivity, if any, has exact field/territory/duration.
- [ ] Purchased Assets Schedule attached/referenced.
- [ ] Excluded Assets Schedule attached/referenced.
- [ ] Brand/trademark treatment defined separately.
- [ ] Background IP treatment defined.
- [ ] Future inventions are not swept in by vague language.
- [ ] Transition support duration/hours defined or reserved for later SOW.
- [ ] Governing law / forum left for definitive agreement if not yet settled.

## Phase 3 — Buyer due diligence

### Corporate / authority

- [ ] Seller legal identity/authority verified for the transaction.
- [ ] Any tax/entity structuring questions resolved with advisers.

### IP / provenance

- [ ] Full Git history reviewed.
- [ ] External contributors/contractors identified.
- [ ] Any needed assignments/licences obtained.
- [ ] AI-assisted development disclosure reviewed under buyer policy.
- [ ] Buzz/JANUS swarm MIT lineage disclosed.
- [ ] Third-party notices verified.
- [ ] Trademark clearance performed if brand transfer matters.
- [ ] Patent counsel consulted if patent rights are negotiated.

### Technical

- [ ] Exact candidate release identified.
- [ ] Full test suite actually executed.
- [ ] Test report preserved.
- [ ] Static syntax/config checks executed.
- [ ] Security review scope agreed.
- [ ] No client-side provider secrets found.
- [ ] Known open production gates disclosed.

### Commercial / regulatory

- [ ] Public prototype status understood.
- [ ] Illustrative economics identified as non-guaranteed.
- [ ] No implied provider partnership inferred from outreach.
- [ ] No gambling/RNG/RTP certification implied.
- [ ] No data-center offload percentage represented as measured without pilot.

## Phase 4 — Definitive agreement

- [ ] Asset Purchase Agreement / IP Assignment prepared by transaction counsel.
- [ ] Exact purchased assets listed.
- [ ] Exact excluded assets listed.
- [ ] Background IP licence/rights, if needed, expressly stated.
- [ ] Third-party/open-source obligations survive transfer.
- [ ] Seller factual reps/warranties limited to diligenced facts.
- [ ] No warranty of revenue/profitability/token price/provider availability.
- [ ] No warranty of regulator approval unless a real approval is included.
- [ ] Liability cap / indemnity / survival periods negotiated.
- [ ] Acceptance criteria are objective.
- [ ] Cure process defined.
- [ ] Payment/escrow release conditions objective.
- [ ] Assignment/change-of-control consents identified for any real contracts.
- [ ] Any non-compete is explicit, narrow, lawful and separately valued.

## Phase 5 — Closing release

- [ ] Feature freeze on closing branch.
- [ ] Exact commit SHA recorded.
- [ ] Exact tree SHA recorded.
- [ ] Full tests rerun on exact closing commit.
- [ ] Per-file SHA-256 manifest generated.
- [ ] Manifest SHA-256 recorded.
- [ ] Release/tag created.
- [ ] Cryptographic signing completed if available/agreed.
- [ ] Closing data-room package finalized.

## Phase 6 — Payment / escrow

- [ ] Signed definitive agreement in force.
- [ ] Escrow agent/payment rail verified independently.
- [ ] Funds confirmed under agreed milestone before control transfer.
- [ ] No transfer based only on screenshot or unverified payment notice.

## Phase 7 — Technical handover

- [ ] Buyer-controlled GitHub organization/repository prepared.
- [ ] Repository transferred/copied as agreement requires.
- [ ] Buyer verifies closing SHA/tree/manifest.
- [ ] Buyer creates its own production accounts/credentials.
- [ ] Seller credentials revoked as appropriate.
- [ ] Personal GitHub/email/MFA credentials are not delivered.
- [ ] Deployment ownership transferred only if expressly included.
- [ ] Documentation package delivered.

## Phase 8 — Acceptance

- [ ] Buyer executes agreed acceptance checks.
- [ ] Exceptions, if any, recorded in writing.
- [ ] Cure period used only for objective agreed defects.
- [ ] Acceptance certificate signed.
- [ ] Final escrow/payment milestone released.

## Phase 9 — Transition support

- [ ] Support start/end date recorded.
- [ ] Included hour cap recorded.
- [ ] Communication/response window recorded.
- [ ] New feature/integration requests routed to separate SOW.
- [ ] Support completion recorded.

## Canonical stop conditions

Do **not** proceed to control transfer if any of the following is unresolved:

- payment/escrow not independently confirmed;
- asset scope still ambiguous;
- a material incompatible licence issue remains unresolved;
- seller lacks authority to transfer a listed asset;
- exact closing snapshot is not frozen;
- buyer demands personal account credentials;
- definitive agreement contains materially broader rights than the negotiated price/scope without deliberate approval.
